# Enclosure STL CAD — parametric Blender generators

Designs/modifies 3D-printed enclosures generated by parametric Blender Python
scripts (e.g. `enclosure/gen_v2.py` — v2 flat terminal; `gen.py` = legacy wedge).

## Workflow
1. **Edit the GENERATOR, never the raw STL**: `.stl` files are outputs. Change the constants/geometry in the script, then:
   `blender --background --python gen_v2.py` (regenerates body/top_plate/battery_door)
   `blender --background --python gen_v2.py -- --preview` (renders preview.png/front/iso/bottom — adds the top view if missing)
2. **Mandatory QA**: `blender --background --python check_watertight.py` (the check scripts use `bpy` → run INSIDE Blender, not system python), + `check_components.py` / `check_bridge_fit.py` / `check_door_components.py` (trimesh via the folder's .venv).
3. **User visual validation BEFORE commit**: previews (iso/top/bottom) sent, the user decides. Zero commit/push before that.

## Bevel lesson (critical — "a lot of mesh problems")
- **Bevel AFTER the booleans = explosion**: 5 588 → 47 788 faces + 1 447 duplicate triangles + flipped normals (negative volume).
- **Bevel BEFORE the booleans** (on the simple shell — the internal cutouts do not touch the perimeter) → ~9-10k faces.
- **Mandatory final cleanup** (booleans on the beveled shell leave duplicates/degenerates): `cleanup_mesh(ob)` — 2 passes of `bmesh.ops.remove_doubles` (dist 0.001) + `dissolve_degenerate` + removal of duplicate faces keyed by rounded **POSITIONS** (booleans create coincidences at different indices) + `recalc_face_normals` (fixes the negative volume). Apply it to the door and the plate too.

## Mesh QA — interpreting the checks
- **Blender is the authority**: `WATERTIGHT body=True door=True` + `non-manifold edges=0` = OK.
- **trimesh `is_watertight: False` is NORMAL** for an enclosure: the "boundary edges" are the design's OPENINGS (top cavity, battery door, USB hole, pockets) — not defects.
- **Negative volume** (trimesh) = flipped normals → `recalc_face_normals` in the cleanup.
- The ~90 remaining duplicates (boolean intersections): 0,3 %; the slicers handle them.

## Component-first: MEASURE the real PCB before drilling
- The USB-C connector orientation varies: **side**, **rear**, or **vertical in the MIDDLE of the board** (cable from underneath — hole in the BOTTOM FACE, not a board-edge notch!). The user corrected a wrong assumption 3× — **ask for or check the documentation** (reference project with the same board, vendor enclosure STL: `/tmp/blockclock-gh/ref/case_orig/files/Case_JC3248W535C.stl`, measure the cutout via trimesh) before implementing.
- Components on the modules (RC522/PN522): the real thickness = PCB + chip + pins (~4 mm, not 3) — the retaining rails must clear the actual footprint.
- Screen corner radius (e.g. r5 on JC3248W535C) → the glass window must match.

## Delegating geometry to Kimi K3 — pitfall and micro-steps
Kimi K3 **analyses endlessly without writing** on complex geometries (5 runs of pure reasoning on the enclosure, zero edits). Remedies:
1. Micro-steps: **1 single action per run** (e.g. "change the H constant 22→29, save, regenerate, verify"), short 300 s timeout — that it will do.
2. Ultra-precise spec: exact coordinates/values (the constants + the lines), never "turn the pocket into a slide".
3. If it still blocks: **implement it yourself** (the generator is readable) — faster than relaunching in a loop.

## Pitfalls
- `check_watertight.py` imports `bpy` → `blender --background --python check_watertight.py`, not python.
- Binary STLs: read the dimensions via `struct` (80-byte header + uint32 n + 50 bytes/triangle) or trimesh (the folder's venv).
- Blender 5: `export_mesh.stl` deprecated → `wm.stl_export` (the script handles both).
